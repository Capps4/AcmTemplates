# 构建与 Fenwick 性能诊断

本文件记录 GNU++17 payload 清理优化之前的 360 行版本，表中的“当前版”指当时诊断版本。后续编译期优化及结果见 [GNU++17 说明](../gnu17/README.md)。

2026-09-30，N=1,000,000、U=2,000,000，GCC 15.2，C++17 `-O2 -DNDEBUG`。修改前后分别进行 5 轮分项测量，每轮交错分项顺序；两份程序串行运行。所有 270 次分项测量均通过结果或状态校验。环境未隔离，不能把两次运行的所有差异都归因于代码修改。

## 主要结论

没有发现 Fenwick 更新、前缀计数、binary lifting 中的异常重复计算。完整 TreeMapOff 接收原始 Key：insert、erase、contains 和 rankOf 都先执行一次 lower_bound；keyAt 无此开销。contains 完全不访问 Fenwick。

| 操作 | 当前版 ns/操作 |
| --- | ---: |
| 原始键 → 坐标（二分） | 89.55 |
| 裸 Fenwick 更新 | 21.35 |
| 裸 Fenwick 前缀计数 | 9.02 |
| 裸 Fenwick 第 k 个坐标 | 56.74 |
| TreeMapOff 插入 | 111.86 |
| TreeMapOff contains | 95.67 |
| TreeMapOff rankOf | 100.88 |
| TreeMapOff keyAt | 62.73 |

这说明二分定位是按 Key 操作的主要成本。表内各项缓存状态不同，不能严格相加或把差值当作精确 profiler 占比。特别是 keyAt 不执行 lower_bound，不能用“定位瓶颈”解释它；其裸选择内核也需要多层依赖内存读取。

诊断的基础混合负载为 50% contains、25% insert、25% erase，包含重复插入和删除不存在的键。当前完整 TreeMapOff 为 **107.77 ns/操作**，std::set 为 **309.65 ns/操作**，约 2.87 倍速度。提前给出坐标、仅维护存在性与计数的裸内核为 **9.14 ns/操作**；它排除了 Key 定位、坐标预处理和映射值存储，不能用这个数字宣称当前通用 Map 接口达到同样速度。

若希望发挥预离散化的小常数，应在预处理阶段一次性把所有操作的键转换为坐标，再对坐标执行内核操作。为通用键额外建哈希表是另一种设计，会增加空间和哈希约束；本次没有为追求特定倍数扩展接口或改变比较器等价语义。

## 构建时间拆分

| 阶段 | 修改前 ms | 当前版 ms |
| --- | ---: | ---: |
| SBT 分配初始化百万节点池 | 0.413 | 0.442 |
| SBT 百万次随机插入 | 211.087 | 183.483 |
| 复制 200 万候选键 | 0.522 | 0.391 |
| 独立排序去重 200 万随机键 | 88.333 | 83.823 |
| Off 构造：复制随机候选、离散化和数组初始化 | 91.867 | 84.801 |
| Off 构造：移动已有序候选、去重和数组初始化 | 18.667 | 1.413 |
| Off 百万次随机插入 | 140.339 | 111.860 |

主评测中的 build 是“空容器构造 + 百万次独立 insert”，不等于 Fenwick 的 O(U) 批量建树。构造时 keys 只是候选，容器初始为空，后续哪些键活跃、值是什么仍由 insert 决定。

若整个初始计数数组已知，裸 Fenwick 线性建树本次为 **3.652 ms / 200 万坐标**，但这个计时排除了排序、键定位、分配归零和 Value 建立，语义及前置条件不同，未替换正式五方 build 成绩。

本分项数据的初始键是从整个 U 中随机取 N 个，查询也均匀覆盖整个候选空间，约 50% 命中。它与主评测初始活跃坐标集中在前半段的分布不同；这里只比较本诊断中的同一序列。

## 实际保留的改动

1. **SBT 展开左右插入分支。** 独立四候选实验在同一进程内交错运行并预热，5 轮构建均快于原版。原版中位 203.375、展开版 185.772 ns/键；前两轮原版波动较大，后 3 轮差异约 3～5%，只作小幅优化看待。混合更新未得到稳定提升；模板化 maintain 的候选未保留。节点池初始化仅约 0.45 ms，占该构建计时约 0.22%，不是主要优化方向。
2. **Off 合并 keys 与 actualKeys。** 只保留一份候选键数组，用等价的实际插入键替换代表。200 万 int 候选少约 8 MB 常驻数据；排序、候选成员关系及活跃条目的首次插入代表不变。Key 移动赋值不抛是该简化的约束。
3. **已有序候选跳过 sort。** 同一 Compare 的 is_sorted 检查通过后直接 unique。这条构造路径从约 18.7 ms 降到 1.4 ms；随机候选仍需排序。末尾才出现逆序的输入会多一次线性扫描，再排序。

仍保留 16B int SBT 节点、原生 vector<bool>、原公开接口。最终头文件 360 行。

在 tree_map_experiments 目录运行：

```bash
g++-15 -std=c++17 -O2 -DNDEBUG -Wall -Wextra -Wpedantic \
  final_results/diagnostics/profile.cpp -o /tmp/treeMapProfile
/tmp/treeMapProfile 1000000 2000000 5
```

预处理、混合负载的状态复制、结果校验及析构在相应计时外，查询循环内含统一加权 checksum。分项记录 work_items：构造/排序/复制为 U，SBT 构造及单操作序列为 N。默认 5 轮不另加预热，完整逐轮数据保留。
