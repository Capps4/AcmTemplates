# 构建优化：同进程前后对照

这是拆分共享排序能力之前、633 行头文件版本的历史实验。当前实现及数据见 [主报告](../../PERFORMANCE.md) 和 [共享排序报告](../adaptiveSorting/README.md)。下方生成脚本要求历史源文件指纹，不能直接输入当前 TreeMap 头文件；共享排序报告保存了恢复该历史版本的补丁。

2026-09-30，GCC 15.2 / arm64，`-std=gnu++17 -O2 -DNDEBUG`。保持 100 万初始键、200 万随机候选、逐次插入语义。正式接口合并到 `_treemap`，全局只导出 `TreeMap` 与 `TreeMapOff`。

## 保留的优化

TreeMapOff 对非 bool 整数、精确 `std::less<Key>` / `std::greater<Key>` 的大候选输入，改用 8 位 LSD 基数排序。负数通过 unsigned 映射与符号位变换处理，降序反转桶编号；某一字节全部相同时跳过散射。少于 1024 个候选或其他键/比较器仍使用 `std::sort`，已排序输入仍直接跳过排序。

临时增加与候选输入等长的键数组，200 万 int 约 8 MB，排序结束即释放；没有增加任何 SBT Node 字段或常驻索引。接口仍是构造空 Map 后逐次 insert，未改成批量导入。

## 同进程候选筛选

每个项目、候选预热 1 次，测 5 轮，每轮随机候选次序；N=Q=1,000,000。复用正式基准的独立线段树 oracle，所有结果流及最终键/值状态通过校验。数值为中位数 ns/实际操作。

| SBT 候选 | 完整构建 | 混合增删 | 命中查询 |
| --- | ---: | ---: | ---: |
| 原版 | 224.714 | 299.364 | 196.293 |
| allocate 加 noinline | 202.498 | 289.892 | 195.616 |
| 按值返回 InsertResult | 236.598 | 310.888 | 201.876 |
| 两者组合 | 224.948 | 325.665 | 202.759 |

| 离线候选 | 完整构建 | 混合增删 | 命中查询 |
| --- | ---: | ---: | ---: |
| 原版 | 198.805 | 111.467 | 90.427 |
| 手写单次比较去重 | 201.132 | 109.739 | 89.008 |
| u32 下标二分 | 202.561 | 124.380 | 92.638 |
| 整数基数排序 | 124.167 | 112.623 | 85.800 |

基数排序把离线完整构建耗时降低约 **37.5%**（约 1.60 倍速度）。查询和更新算法未改，不能把其小幅波动归因于排序优化。手写二分更慢，去重没有明显收益，均不保留。

## 拆分构建与复核 SBT

另用独立的插入循环，同进程交错 4 个候选，各预热 1 次、测 7 轮。这里不沿用正式基准计时内的逐结果哈希，计时外完整检查键、值、size 和成功插入数。因此与上表只比较各自内部的前后差异，不混用绝对数值。

| 候选 | 构造阶段 ms | 百万次插入 ms |
| --- | ---: | ---: |
| SBT 原版 | 0.418 | 187.265 |
| SBT noinline | 0.412 | 183.982 |
| Off 原版 | 84.407 | 99.002 |
| Off 基数排序 | 15.740 | 99.045 |

离线构造阶段包含候选复制、排序去重和数组初始化，耗时降低 **81.4%**，后续插入基本不变，改善来源明确。节点池初始化不足 0.5 ms，不是 SBT 构建瓶颈。

SBT noinline 首轮看似有约 10% 收益，但反汇编显示原版已经独立调用 allocate：insertNode、allocate、maintain 的有效指令分别为 195、159、139 条，两版本归一化地址和符号后相同。外层 measure 的代码布局和栈帧不同，不能据此解释为缩小递归函数。独立插入循环复核只剩约 1.8% 中位差异，noinline 单轮还出现 284 ms 波动。**不保留此属性，SBT 算法维持原实现**，也不把最终五方跑分的跨轮变化当作 SBT 优化收益。

桌面环境未隔离，全部原始数据和单轮范围应一起参考。筛选共 144 次执行、独立分项共 32 次执行均通过结果校验。

## 正确性与文件

新增回归覆盖不同整数宽度、有符号端点、升降序、1024 阈值两侧、重复/有序/逆序输入、先跳过后散射以及散射后跳过字节、自定义/透明比较器与字符串回退。正式检查及五方基准见 [主报告](../../PERFORMANCE.md)。

- [SBT 筛选原始数据](screenSbt.csv)、[离线筛选原始数据](screenOff.csv)、[构建分项原始数据](buildStages.csv)。
- 同名 `.log` 保留逐轮校验；各候选 `.patch` 保留与原版的差异，没有额外生产头文件副本。
- [最终改动](optimization.patch)、[源文件指纹](sourceSha256.txt)、三个 `.cpp` 是复现材料。

在 tree_map_experiments 下生成临时候选并运行分项：

```bash
candidateDir=$(python3 final_results/buildOptimization/prepareCandidates.py)
g++-15 -std=gnu++17 -O2 -DNDEBUG -Wall -Wextra -Wpedantic \
  -I "$candidateDir" final_results/buildOptimization/buildStages.cpp -o "$candidateDir/buildStages"
"$candidateDir/buildStages"
```

替换最后两步中的 `buildStages` 为 `screenSbt` 或 `screenOff` 可复现筛选。生成脚本通过补丁恢复原版及候选，先核对本轮源文件指纹；需要 `patch`。完整五方对比仍使用根目录 `bash runBenchmark.sh`。
