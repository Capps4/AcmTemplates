当前 ListHelper sorted 与 TreeMap 原内置 sortKeys 对比
日期：2026-10-01。环境：macOS 15.7.4 arm64，GCC 15.2/libstdc++，Apple Clang 17/libc++。
编译：GNU++17 / C++17，-O2 -DNDEBUG -Wall -Wextra -Wpedantic -Werror。

来源与边界：
1. 新实现来自当前安装的 VS Code ListHelper.code-snippets，完整快照为 CurrentListHelper.code-snippets。
2. 旧 sortKeys 从此前删除内置排序时保留的恢复补丁恢复；为最终 64 行私有排序，不是更早的固定 8 位版本。
3. 同一 TreeMap 源码生成三个命名空间，除排序调用和 include 外，构造、去重、Fenwick 与 Value 初始化一致。
4. sortedDirect 直接执行 keys = std::move(keys) | seq::sorted(compare)。
5. sortedBridge 保留当前 TreeMap 的兼容逻辑：先 sorted() 升序，再为 greater 反转。
6. 正式 treeMap.hpp 和 ListHelperAdaptive.hpp 均未修改；工程中那个共享头文件仍是上一版。

测量方法：
预热一轮，正式七轮，随机打乱方法顺序，取中位数。每个配置输出逐次完整比较。
两编译器串行运行，各 2268 条正式计时记录，总计 4536 条。
sort：输入副本准备在计时外，计入扫描、基数临时缓冲、排序及回写。
ctorMove：复制准备在计时外，候选 vector 移动传入，计入排序、去重和三个 sidecar/Fenwick 数组初始化。
ctorCopy：直接以左值候选 vector 调用构造函数，额外计入参数复制。
构造后的 Map 初始为空；不包含随后逐次插入活跃键的时间，也不包含析构。
计时后每个 Map 插入最多 4096 个样本并验证 rankOf/keyAt/optional false/完整遍历。
Clang C++17 ASan/UBSan 另通过 TreeMap/TreeMapOff 差分与回归检查。
桌面环境未隔离，数字是本机实测，不保证跨机器收益。

代码差异解释：
普通大随机整数两者均已具备 8/11 位选择与恒定桶跳过，过去共享版落后 16%～18% 的情况不再普遍存在。
旧 sortKeys 对 vector 的每次散射结束直接 swap；新通用版交替读写两个缓冲，最后停在临时缓冲时多一次回写。
此外，旧版前向散射/独占前缀和，新版反向散射/累加前缀和，位宽准入规则也不同。
间隔值域观察到明显退化，但未通过单因素实验把差距分摊到回写、散射方向或代码生成，不能全部归因于管道调用。
512 个全宽 int：GCC sortKeys 1.891us / sorted 2.717us，Clang 1.974us / 2.408us。
该长度旧版成本模型允许基数排序，新版 256×passes 阈值选择 std::sort；这是排序策略不同。
新版已支持 typed greater；直接传 compare 可删去旧升序后反转适配，且避免已降序输入两次反转。
