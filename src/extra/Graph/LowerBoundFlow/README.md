# LowerBoundFlow

[code.hpp](code.hpp)

`LowerBoundFlow<T>(n)` 维护 n 个点的有向图，点从 0 开始。T 为有符号整数，边界 `0 <= lo <= hi`，所有边的 hi 之和必须可由 T 表示；内部据此安全计算需求和有限流量上限。支持平行边、自环、零容量；n+2 及全部残余边编号须可由 int 表示。

- `add(s,t,lo,hi)` 返回从 0 开始的原边 ID，同时令旧答案失效。
- `work()` 判定可行环流，成功时所有点满足流入等于流出。
- `work(s,t)` 要求 s != t，返回 `optional<T>` 的最大非负 s-t 流值。负流值不在支持域；只有负值可行时同样返回 nullopt。源点净流出、汇点净流入等于答案，其他点守恒。
- `get(id)` 返回最近一次成功 work 的该原边流量。失败后或 add 后不得读取，调试模式会断言。

每次 work 都从原边表重建，可重复求解、切换源汇或在追加边后重算；不会延续上次残余网络。图和结果均由对象拥有。

直接复用 core `Flow<T>`：先需求平衡，再去掉辅助边及其反向残余，最后增广。时间不超过两次 O((n+2)²(E+n)) 的 Dinic，空间 O(n+E)。继承 core MaxFlow 的递归增广路径限制，不能据此声称任意深链安全。

参考 [Luzhiled Max Flow Lower Bound](https://ei1333.github.io/library/graph/flow/maxflow-lower-bound.hpp) 的上下界归约，保留本仓 Flow 的接口与容量检查。

正确性用例用小图上下界、边流的独立穷举判断存在性和最大值，并逐边核对范围、守恒、重建、失败及整型上界。性能用例为已知最优值的并行两段路径和成对回边，检查恢复流。本机计时见测试报告，尚无 OJ 排名证据。
