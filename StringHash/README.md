# StringHash / GNU++17

实现收进 `_strhash`，内部模板为 `Impl<D,B,P>`，维度、模数、底数分别为 `d`、`p`、`b`；外部只导出 `StringHash` 类别名。构造函数的序列参数名为 `List`。C 字符串通过 string_view 读取，字符按 unsigned byte 编码；支持负整数、signed/unsigned 极值及 vector<bool>。

默认底数由时钟 seed 初始化的 mt19937_64 生成，均匀取自 `[p[k]/2+1,p[k]-1]`，严格大于模数的一半。生成器为 inline 辅助函数内的局部 static，每次运行初始化一次。C++17 inline 数组保证不同编译单元使用同一底数、模数及对应模板实例；单次运行中的对象可互相比对，不同运行的哈希值不保证一致。可复现结果可用具有静态存储期的固定 int 数组作为 `_strhash::Impl<D,B,P>` 参数，每个维度要求 `P>1`、`0<B<P`，构造后不能修改参数数组。

共享幂表 `pw` 从全 1 的零次幂开始，构造时扩展到当前序列长度，`getArray` 不再检查或扩展幂表。构造时间 O(D*n)，查询 O(D)，空间 O(D*n+共享幂表)。同一模板实例的构造若需要扩展幂表，需外部同步；构造结束后，查询只读取前缀及幂表。提前计算可减少查询开销，但只构造不查询、或仅查询很短子串时，首次构造会计算更多幂。

序列长度须小于 INT_MAX；下标从 0 开始，区间为 `[l,r)`，空区间各维度为 0。`getU64(l,r=-1)` 将 1/2 维哈希无损装入 64 位，r=-1 表示到结尾；D>2 使用 getArray。比较子串时同时比较长度，哈希仍有碰撞可能。C 字符串需要非空指针及 NUL 终止；含 NUL 的数据使用 string/string_view 或字节容器。输入仅在构造期间读取，前缀哈希由对象持有。

本模块 GCC -O2 及 Clang ASan/UBSan 检查通过：独立 unsigned __int128 多项式 oracle 逐区间比对，覆盖先查空区间、随机字节/NUL、整数极值、vector<bool>、1/2/3 维、临时 string、幂表增长后旧对象及副本查询、底数范围、跨编译单元的数组地址和哈希一致性。

性能基线为本次修改前的 Final，原样保存在 `BenchmarkBefore.hpp`，不是 Original.hpp。旧/新使用相同的运行时底数、模数、50 万字符输入及查询列表；每个场景预热一次、计时七轮取中位数，校验和一致。冷启动通过九组不同地址的底数数组生成独立模板实例，校验、预热及七轮计时各使用一次，确保每轮幂表均从零次幂开始；构造场景通过编译器屏障保留对象的完整构造。热场景先将双方幂表扩展到整串长度。

本次测得：50 万次随机子串查询约快 1.17x，短子串查询约快 1.19x，热缓存下构造加查询约快 1.06x；热构造基本持平。首次只构造的耗时从 3.740 ms 增至 5.120 ms，约增加 37%；首次构造加整串查询为 4.604/4.620 ms，基本持平。随机生成器初始化发生于计时前，本报告不测进程启动耗时。完整七轮数据、底数、编译命令及源码 SHA256 见 Results.json，当前表格见 [Performance.md](Performance.md)。
