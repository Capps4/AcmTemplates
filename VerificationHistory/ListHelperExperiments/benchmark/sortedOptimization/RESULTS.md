# sorted 分步骤优化与独立验证

2026-10-01，本机 macOS arm64，GCC 15.2 和 Apple Clang 17，性能编译 -O2 -DNDEBUG。基线从当时安装的 ListHelper.code-snippets 直接展开，保存于 Baseline.code-snippets / before.hpp。Baseline.hpp 只改命名空间并取消全局导出，避免对照冲突。

最终排序核心 75 行，含 vector 类型识别、radixSort 和 sorted；Sorted.hpp 共 99 行。完整 ListHelper 中其他算子保持原样，新 snippet 的展开与完整最终头文件一致。

## 逐项结果

每项只比较本项的数据，单位 ms，5 轮中位数。输入为百万 int；比较器识别组使用 22 位随机值域，恒定桶组使用 8 位随机值左移 16 位。以上均按 unsigned / 相对值处理，覆盖负值。

| 改动 | 编译器 | 改动前 | 改动后 |
| --- | --- | ---: | ---: |
| 识别 less<int>，8 位内核不跳桶 | GCC | 40.327 | 3.711 |
| 识别 greater<int>，8 位内核不跳桶 | GCC | 40.123 | 3.722 |
| 识别 less<int>，8 位内核不跳桶 | Clang | 41.328 | 3.841 |
| 跳过恒定桶，仅比较 8 位内核 | GCC | 5.200 | 4.017 |
| 跳过恒定桶，仅比较 8 位内核 | Clang | 5.118 | 4.386 |

类型识别带来的主要收益是让原本回退 std::sort 的标准比较器进入整数快速路径。已有默认 less<> 的百万 22 位随机组基本持平：GCC 3.732 / 3.777 ms，Clang 3.595 / 3.610 ms。恒定桶检测在连续 8 位值域组也基本持平：GCC 2.234 / 2.254 ms，Clang 2.480 / 2.466 ms；不能把这些小幅波动解释成固定比例。

## 8 / 11 / 15 位

使用相同的比较器识别、恒定桶跳过、缓冲区、候选准入条件，仅改变每轮位宽。下面为 GCC 同组中位数，单位 ms。

| 输入 | 8 位 | 11 位 | 15 位 |
| --- | ---: | ---: | ---: |
| 百万 int，22 位随机值域 | 4.143 | 3.418 | 4.280 |
| 百万 int，完整 32 位随机 | 4.928 | 4.285 | 6.722 |
| 百万 long long，完整 64 位随机 | 9.518 | 7.841 | 10.396 |
| 4096 个 int，完整 32 位随机 | 0.01408 | 0.01235 | 0.05622 |
| 百万 int，低 16 位恒定 | 4.322 | 5.771 | 3.578 |

15 位使用 32768 个 size_t 桶，本机约 256 KiB；8 / 11 位分别约 2 / 16 KiB。15 位在某些稀疏键上受益，但对普通随机输入及小数组常更慢。保留它需要增加识别稀疏位段等策略，为保持代码简洁，本次没有采用。

最终规则：n >= 256 且 n >= 256 × P8 才进入基数排序；P8 = ceil(bits / 8)，bits 来自 max-min 的有效位数。默认 8 位，n >= 4096 且 ceil(bits / 11) < P8 时选择 11 位。沿用原来的常数 256，仅增加位宽选择的一条简单规则。

## 最终实现的独立验证

更换种子，增加 384、1536、4095、4097、32768、131072、750000 等长度及 12 / 20 / 24 位值域，并复测 4096 边界、百万随机、升序、倒序和近乎有序输入。本组实际调用最终 Sorted.hpp，未用调参候选代替最终实现。

单位 ms，均为同一输入和同一编译器下的 5 轮中位数。基线为安装 snippet 中的旧 sorted。

| 百万输入 / 比较器 | GCC 原版 | GCC 最终 | Clang 原版 | Clang 最终 |
| --- | ---: | ---: | ---: | ---: |
| int，22 位随机，less<> | 3.637 | 2.963 | 3.568 | 2.885 |
| int，22 位随机，less<int> | 39.436 | 2.967 | 39.725 | 2.901 |
| int，22 位随机，greater<int> | 39.488 | 2.962 | 39.789 | 2.961 |
| int，完整 32 位随机，less<> | 4.381 | 3.689 | 4.321 | 3.607 |
| long long，完整 64 位随机，less<> | 7.997 | 6.646 | 7.938 | 6.729 |

每种编译器的独立组先对每个配置取中位数，再对“新耗时 / 旧耗时”取等权几何平均：

| 组别 | 配置数 | GCC 耗时变化 | Clang 耗时变化 |
| --- | ---: | ---: | ---: |
| 默认随机整数，混合长度 | 68 | -6.7% | -6.8% |
| 默认随机整数，n >= 4096 | 44 | -10.7% | -10.1% |
| 间隔值域输入 | 18 | -33.5% | -28.6% |
| 已有序 / 倒序输入 | 16 | +0.3% | +0.5% |
| 百万随机 typed less / greater | 4 | 原耗时约 12.6 倍 | 原耗时约 12.7 倍 |

不是每个配置都更快：默认比较器下最差单个配置，本次 GCC 约慢 6.5%，Clang 约慢 6.8%。小数组、有序输入和部分不减少轮数的值域通常接近原版。上述几何平均不代表任意实际应用的数据权重，不保证其他机器具有相同收益。

## 方法与校验

- 每项先预热一次，再测 5 轮，随机打乱方法顺序；对短输入，每轮重复至累计排序时间约 1 ms 或 256 次上限。
- 输入准备 / 复制在计时外，计时中以非 const 右值进入真实管道；包含排序判定、范围扫描、临时缓冲和桶操作。左值复制语义通过功能检查验证，没有将复制成本隐藏地归入通用端到端结论。
- 每次计时后完整比较输出与 std::sort 的结果，包含全部重复值；编译器屏障位于计时边界。入口函数统一 noinline、64 字节对齐。
- 两种编译器的性能程序串行执行，最终独立复测在编译和功能检查完成后单独运行。桌面未隔离，结果包含运行噪声。
- 四个阶段每种编译器分别为 1080 / 360 / 1200 / 2280 个正式样本，共 9840 个；全部通过完整结果比较。
- GCC GNU++17、GCC 严格 C++17、Clang C++17 ASan/UBSan 各通过 29129 项检查，-Werror 编译无警告。覆盖 8/16/32/64 位有符号 / 无符号整数极值、宽度与长度边界、左右值语义、四种标准比较器、bool/string/array/deque、自定义移动专用比较器、移动专用元素及 pmr allocator。
- 核心代码不增加链表支持。VS Code 中安装的旧 snippet 本次未改动，最终替换文件另行提供。
