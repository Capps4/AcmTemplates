# 模板实现与验收规范

本规范来自用户要求、语雀当前模板及仓库差异审查。常驻入口是根目录 AGENTS.md。代码正确性、性能、简洁性按此顺序取舍。

## 适用范围与判定

现用算法实现由 Manifest.json 确定，包括 code.hpp、Geo2 的四层源码、直接前置 Include.hpp 和 Headers 头。测试及工具沿用各自语言和职责的命名习惯；仅在算法接口变化确实需要时修改引用。算法放 src/，公共头放根目录 Headers/，正确性放 tests/Correctness/，性能放 tests/Performance/，工具放 tools/。

- **error（确定违规）**：例如逻辑 `||`、公共头入口错误、本仓 include 丢失、严格编译参数缺失或被降低，必须修复。
- **review（待审候选）**：长名、压行、typedef、模板判断和 `&&`。先区分公共接口/局部名字、语法及所有权，再修复或记录保留理由。候选数量不是违规数量。
- **kept（已解释保留）**：tools/RuleExceptions.json 中按文件、规则、符号及候选代码指纹登记。禁止仅用“保持现状”“方便”“通过过测试”作理由；公开接口、外部协议、经典名称和必要类型分派需写清对应契约。
- **R00（过期审查）**：候选消失或其代码指纹变化时，旧记录不能继续使用。重新检查含义后更新，已删除的候选移除记录。不得整批接受新候选或只刷新指纹。

检查入口为 `ctl rule`，完整报告保存到 `.cache/reports/Rules.json`。错误和未处理的审查候选均返回非零。扫描结果不替代语义审查及运行验证。

## R01 正确性优先

先明确支持域、前置条件和返回约定，再比较写法。宽乘、边界检查、字节转换、深链安全、动态模缓存失效等必要保护不能为减少行数而删除。

## R02 正确性证据

算法、模板类型或生命周期改动在定版前必须通过以下验证：固定 corner case 与历史回归；小规模穷举或独立朴素 oracle；固定种子的随机对照；大规模和极限结构。适用时使用 GCC/Clang、ASan/UBSan。每类用例解释所覆盖的风险，不以用例数量替代覆盖质量。测试使用独立 oracle。

按用户授权范围执行验证。当前 scoped-code-changes 流程默认只做 diff Review；明确请求局部检查后执行对应检查，“全量自测”才执行全库编译和测试。没有运行就标待验证，不能称为定版、测试通过或性能达标。

## R03 性能目标

用户目标是：用于相关算法题时，直接写法不能慢于多数 OJ 的性能前 5% 提交。选择代表题和强实现，同机器、输入、语言版本和参数测量，再通过获准的实际 OJ 提交验证。保存题号、平台、时间、语言、编译器、样本范围和可核实的排名分布。没有排名证据时只报告本机对照结果，标记 OJ 目标待验证。

## R04 命名

内部变量优先 1–4 字符：左右 l/r，语义对称的 a/b，规模 n/m，父亲 fa、深度 dep、大小 siz、计数 cnt、距离 dis、模数 mod、逆序表 rev。名字必须能从局部上下文解释；确实无法再拆清楚时可用长名并说明。经典算法名、公共接口、模板类型名不机械缩写，接口变化另行确认。

参数、捕获、局部结构体字段和私有成员同样适用；私有辅助函数用简短动词表达职责，例如 init、fit、put、qry、seek、join。类型保留经典算法名，常量保持清楚的边界含义。std/C 库符号、编译器属性和既有公开字段按外部或公共协议处理，不能只改本仓调用位置。

重命名按符号和作用域处理，不替换注释/字符串，不连带修改 .first/.second 等库成员。检查遮蔽、自初始化、移动后的参数、模板参数及宏绑定。不能通过给所有候选套“公共 API”来绕过内部命名修复。

## R05 换行

默认展开循环、条件分支及多步操作。不要在一行串接执行语句，不用逗号运算符压调用。短纯返回/getter 可在人工确认更清楚时例外；不得借例外堆叠控制流。模板声明单独成行。根目录 .clang-format 提供排版基础，不能代替语义审查或手工判断。

## R06 压行比例

按文件和模块分别计算，最多 30%。分母是去除空行、纯注释、预处理行后的源码行；分子是把多步操作或控制流主体压到同一行的行。for 头的两个分号、普通多变量声明、短纯返回 getter 不机械计入。跨行语法和宏需要人工审查；自动检测只标候选。30% 是上限，不应主动向上限靠拢。

自动扫描排除括号内分号及预处理续行，并分别定位多语句和同一行的控制流主体；报告的 candidatePercent 仅是多语句候选比例，不能直接当实际压行比例。人工核对后合并控制流主体候选，按文件及模块重新计算。宏只在确实减少重复定义时保留并说明，不能借宏压普通算法流程。

## R07 and/or

C++ 逻辑与/或使用 and/or。引用、转发引用、引用限定及宏引用参数仍用 &&。不改字符串、注释、Python、shell 等其他语言。替换必须审查语法用途，不能全文替换所有 &&。

## R08 C++17

优先 using、inline 变量/静态成员、必要的 if constexpr、结构化绑定和适当的 string_view。现代特性应减少重复或明确类型；不能为了现代化增加模板层或改变对象生命周期。

## R09 模板判断

enable_if、void_t、conditional_t 等必须有重载、所有权、表示或性能原因。没有原因的分支可以去掉；有原因时选择最短清晰写法。删除支持类型或更换所有权语义属于契约变化，先确定范围。

逐处记录被保护的类型/调用场景，以及删除后会改变的行为。编译期判断没有运行时分支，但仍需控制维护复杂度；只判断 enable_if 数量不能认定过度设计。继承 std::is_convertible 等需要类型的场景不能机械换成布尔 _v；自定义 trait 没有现成 _v 时不额外造一层别名只为外观现代化。

## R10 原结构和接口

参考语雀的算法流程、短名、功能开关与接口习惯，保留 现用实现 的正确性修复和有证据的性能内核。新增公共接口、常驻状态、大幅重写或删除现有支持域逐模块确认。语雀自身也有压行和复杂模板，不能整块覆盖 现用实现。

## R11 契约和注释

用短说明记录索引/区间、合法类型/值域、单位元、误差、容量、reset 或重复 work、时间与空间复杂度。注释解释不变量、必要例外、选择原因，不逐句翻译代码。

## R12 生命周期

明确左值借用、右值拥有、const 不破坏、reset 导致的失效，以及共享池/持久化的规则。不能为删 traits 引入悬垂引用或破坏 COW。vector<bool>、视图、临时值返回等已支持用法需要专项验证。

## R13 优化和阈值

缓存、分派、强制 inline 和阈值必须有实测收益与代表分布。记录原始样本、checksum、平台和源码指纹；比较构建、预处理、查询、修改各自成本。不要把不同场景倍率取平均称为总体提升，也不拿旧机器计时作为现版证据。

## R14 迭代和递归

按目标规模和最大深度选直接实现。不能为短代码删除树/图的深链显式栈；用户指定 SCC / EdgeBC / VertexBC 使用直接递归 DFS，这三个模块按该要求实现，保留 Tarjan 分量栈并记录调用栈限制。保留递归时需说明并验证支持的最大深度。MaxFlow 的深路径风险单列，未验证不宣称安全。

## R15 实现与验证隔离

现用源码、测试和 oracle、工具分别放 src/、tests/、tools/；标准头放 Headers/。src/ 不放存档和测试程序。仓内不留 .code-snippets、旧 benchmark、历史快照和编译产物；构建及运行报告生成到忽略的 .cache/。语雀 token 独立保存于忽略的 .yuque/token，权限 600；非秘密配置不得混入 token。

## R16 决定与同步

每模块记录差异、保留理由、拟简化项及验证计划。公共头和等价风格整理不替代模块定版。涉及算法/接口/支持域的选择由用户逐项确定。语雀同步仅替换已确认卡片的 code，保留标题、ID、折叠及其他属性；当前任务未明确授权时不写正式代码、不 Git commit/push。

## R17 严格编译要求

所有现用模板必须能够通过以下参数的编译，不能关闭警告或移除调试宏规避：

```text
-std=gnu++17 -Wall -Wextra -Werror -Weffc++ -O0 -g -D_GLIBCXX_DEBUG
```

tools/__init__.py 的 strict 配置包含这些参数，并保留诊断用的 `-rdynamic -fno-omit-frame-pointer`。严格编译后的测试也运行，检查 GNU 标准库调试模式中的迭代器与容器约束。此模式的相关翻译单元必须使用一致配置，不能混用容器 ABI。优化版正确性检查和 sanitizer 分别运行；性能计时保持优化配置，不以调试版耗时评价算法性能。

## R18 头文件层次

标准头入口为 Headers/Headers.hpp，其同目录 Std.hpp 为 Clang 等环境提供标准头清单。有模块依赖时，code.hpp 先 include 本模块 Include.hpp，前置层仅包含直接依赖；无依赖时直接使用公共入口。Geo2 保留 PointVec→SegLine→PolygonConvex→Circle 的源码链，由 PointVec 引入 Include.hpp。

现用头必须有 pragma once，本仓引号 include 应存在且留在本仓范围内。禁止靠本机绝对路径或间接的无关模块补头文件。新增依赖同步更新 Manifest；扫描记录不代替跨翻译单元编译。

## 模块实现约束

Debuger 严格使用 strdup 配置和 COMPETITION_DEBUGER 宏；FastInputOutput 使用 Qinput/Qoutput 接口并保留 cin/cout 两个 ref 宏。ListHelper / Discreter / Tree 维持既有接口和算法，只补实际正确性问题。图论类直接用 SCC / EdgeBC / VertexBC，连通性 DFS 直接递归，不保存 Frame；MaxFlow / GridUtil / RingTree / TopSort 保留现用实现。

HashMap 的 Impl / Pool 保持共享池和 owner 隔离实现，允许适度排版到 200–210 行；SegTree 目标 230 行，允许合并连续的对称下标更新及短函数，人工统计压行仍不得超过 30%。其他位置继续默认展开。

GridUtil 保留 static constexpr int D=4，方向数组 dx[D]/dy[D]、循环上界和 reserve(D) 共用 D；改为八方向时同步补齐方向数组。

FFT / NTT 实现各自放在 _fft / _ntt，供使用的别名放在命名空间外：FFT 为 Float=double、Poly=_fft::Polynomial<Float, std::complex>，NTT 为 Poly=_ntt::Poly。直接使用全局 Poly；组合测试只在生成源码中临时改名并立即撤销宏，不给模板增加冲突规避配置。NTT 系数直接写 Z，不设 T 别名；root() 从 Z::getMod() 编译期求原根，按用户要求允许短判断及试除循环适度压行；Z 的模数必须是编译期固定的质数，NTT 长度为整除 p-1 的 2 次幂。

ModuloInteger 的长整型模乘使用 long double 估商和精确残差校正。inline 不用于防止同一头重复包含：模板/类内函数和 constexpr 函数不需额外 inline；头中的非模板定义、共享状态和明确的性能内联保留必要 inline。
